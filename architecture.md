# Architecture Overview

<!-- This document orients readers to the SHAPE of this repository. SDK
     internals are documented separately — see the adapter architecture
     spec for those. This file focuses on what wraps the SDK: the
     reference application, the template layer, and the build tooling. -->

This repository contains **two things** living in one place:

1. The **dAppBooster SDK** under `src/sdk/` — interfaces, adapters, hooks, and components for building blockchain UIs. The SDK is the product; everything else is a consumer of it.
2. A **reference application** wrapping the SDK — routes, page components, demos, theme setup, env handling. The reference app is what runs when you `pnpm dev`. It doubles as the template that `create-dappbooster` will eventually scaffold from.

Read the adapter architecture spec (linked below) for SDK structure. Read on for the application layer.

## Repository layout

```
src/
  sdk/                 → the SDK (see adapter architecture spec)
  chakra/              → Chakra style package consuming the SDK's headless components
  components/          → application UI (page components, shared components, theme shell)
  routes/              → TanStack Router file-based routes
  contracts/           → ABIs and contract definitions (codegen output lands here)
  data/                → subgraph adapters and queries
  transactions/        → Chakra-styled TransactionButton + SignButton (app-level)
  tokens/              → token list infrastructure (lists, search, selection UX)
  wallet/              → wallet connector configs and runtime initialisation
  env.ts               → Zod-validated environment variables
  main.tsx             → application entry point
  routeTree.gen.ts     → generated by TanStack Router (do not edit)
docs/
  architecture/        → SDK architecture spec and overview (the source of truth for SDK shape)
  pages/               → hosted documentation (built by Vocs, deployed to docs.dappbooster.dev)
scripts/
  codegen.ts           → codegen orchestrator that discovers adapter plugins
```

The split between SDK and app/template will become more explicit at monorepo extraction time, when `src/sdk/*` moves into `packages/*` and the app layer becomes a sibling.

## The SDK

`src/sdk/` is the entire SDK surface — adapters, core interfaces, React hooks, headless components, codegen orchestrator. Every architectural decision about how the SDK works lives in **[`docs/architecture/adapter-architecture-spec.md`](docs/architecture/adapter-architecture-spec.md)** and the focused subdocuments under [`docs/architecture/adapter-spec/`](docs/architecture/adapter-spec/).

If you need to understand how `useTransaction` works, how adapters compose, what the escape hatch progression looks like, or how to add a new chain type, that spec is the answer. This file does not duplicate it.

## The application layer

What lives in this repo *besides* the SDK.

### Routes

`src/routes/` is a TanStack Router file-based tree. `__root.tsx` builds the provider stack: `ChakraProvider` → `DAppBoosterProvider` → app shell. The provider stack is the boundary between framework setup and feature code; every demo and page sits inside it.

Routes use the `.lazy.tsx` extension for code-split lazy loading. Plain `.tsx` is reserved for routes that must be eagerly loaded. `routeTree.gen.ts` is regenerated by `pnpm routes:generate` (and watched by `pnpm dev`).

### Page components

`src/components/pageComponents/` holds page-level UI. The home page lives here, including the `Examples/` directory with one demo per SDK feature (TransactionButton, SignButton, TokenInput, SwitchNetwork, ENS resolution, HashHandling, OptimismCrossDomainMessenger). The demos are the practical entry point for someone learning what the SDK can do — each one is a runnable example calling SDK hooks.

`src/components/sharedComponents/` holds reusable UI primitives the app uses across pages — `Avatar`, `BigNumberInput`, `ExplorerLink`, `Hash`, `HashInput`, the connect button, the wallet status verifier. Some of these will graduate to the Chakra style package over time.

### Theme and UI shell

`src/components/ui/` configures the Chakra system: provider, color mode, toaster, tooltip. The theme is defined via `createSystem(defaultConfig, ...)` and exposes semantic tokens (`bg`, `primary`, `text`, `danger`, `ok`, `warning`) that support light/dark mode out of the box. Fonts are Manrope (body, heading) and Roboto Mono (code).

`src/chakra/` is the headless style package surface — `ConnectWalletButton` and `WalletGuard` wrap the SDK's headless render-prop components with Chakra markup. This directory will eventually become the `@dappbooster/chakra` package.

### Env handling

`src/env.ts` validates the runtime environment with Zod via `@t3-oss/env-core`. Every variable is `PUBLIC_*`-prefixed (Vite convention) and typed. Access env values via `import { env } from '@/src/env'`; never read `import.meta.env` directly. Adding a new variable means editing both `.env.example` and the Zod schema.

### Build and tooling

- **Vite 6** builds the app. Manual chunk splitting groups vendors (wagmi, web3 libs) for cacheability.
- **TanStack Router CLI** generates `routeTree.gen.ts` from the `src/routes/` tree.
- **`pnpm codegen`** runs the codegen orchestrator at `scripts/codegen.ts`. The orchestrator discovers adapter codegen plugins under `src/sdk/*/codegen/` and from installed packages declaring a `dappbooster.codegen` field in their `package.json`.
- **Vitest** runs the test suite with a jsdom environment.
- **Biome** handles formatting and linting in one tool.
- **Husky** wires three git hooks: lint-staged + Vitest on pre-commit, commitlint on commit-msg, full `tsc --noEmit` on pre-push.

## Tech stack

| Category | Technology | Notes |
|----------|-----------|-------|
| Language | TypeScript 5 (strict, ESM) | Path aliases: `@/src/*`, `@packageJSON` |
| Framework | React 19 | StrictMode enabled |
| Blockchain | wagmi 2 + viem 2 | Type-safe Ethereum interaction; peer deps of the EVM adapter |
| State / data | TanStack Query 5, graphql-request | Suspense-based contract reads |
| Routing | TanStack Router | File-based with auto code-splitting |
| UI | Chakra UI 3 + Emotion | Semantic tokens, light/dark mode |
| Env validation | Zod + @t3-oss/env-core | All vars `PUBLIC_`-prefixed |
| Build | Vite 6 + SWC | Manual chunk splitting for vendors |
| Test | Vitest + Testing Library | jsdom environment, colocated test files |
| Lint / format | Biome | Format + lint in one tool |
| Package manager | pnpm 10.30.2+ | Enforced via `packageManager` field |
